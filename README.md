# UnpackModel v3

Консольная версия обработчика архивов макетов без веб-интерфейса.

Также доступна отдельная локальная операторская панель. Она не связана с
основным проектом Image Magic/FastAPI и по умолчанию слушает только localhost.

```bash
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m web.app
```

Откройте `http://127.0.0.1:8016`. Разрешённые рабочие каталоги и адрес можно
задать переменными окружения:

```dotenv
UNPACK_ALLOWED_ROOTS=/путь/к/архивам:/путь/к/результату
UNPACK_WEB_HOST=127.0.0.1
UNPACK_WEB_PORT=8016
UNPACK_WEB_STATE_PATH=.web_state/state.json
```

Панель сначала строит и показывает полный план имён. Заказы, решённые
правилами, переименовываются автоматически. Предложения LLM ждут оператора и
разделены на две группы:

- **«Есть вопросы — нужна проверка»** — показываются первыми, под каждым
  заказом видна причина: ошибка или предупреждение, файл без предложенного
  имени, повторяющиеся имена или уверенность LLM ниже порога;
- **«Уверенные — можно подтвердить пакетом»** — всё остальное; кнопка
  «Подтвердить все уверенные (N)» применяет их разом. Заказ, который не удалось
  применить, переходит в «Есть вопросы» с причиной.

Порог уверенности задаётся `UNPACK_CONFIDENT_THRESHOLD` (по умолчанию `0.85`).
Необратимые действия («На ручную проверку», «Остановить запуск»,
«Подтвердить все уверенные») подтверждаются повторным нажатием той же кнопки в
течение 4 секунд — без системного окна `confirm()`, которое встроенные
браузеры молча блокируют.

Панель работает только с папками из `UNPACK_ALLOWED_ROOTS` (через `:`); по
умолчанию разрешена лишь папка проекта. Новый запуск невозможен (HTTP 409),
пока в предыдущем остались отложенные или нерешённые заказы. Доступны подтверждение с ручной
правкой имён, откладывание и перенос в ручную проверку. Интерфейс рассчитан на
доверенную локальную сеть и не запрашивает логин или пароль.

Она:

1. безопасно распаковывает ZIP и RAR;
2. получает подзаказы через API sborka.ua;
3. проверяет количество файлов и сторонность заказа;
4. определяет лицо и оборот дешёвыми эвристиками по именам файлов;
5. целиком проверяет план переименования;
6. атомарно переименовывает макеты;
7. кладёт исходный архив прямо в папку заказа рядом с макетами как резервную
   копию (архивы из старой скрытой `.source_archive/` переносятся туда же); спорные
   заказы переносит целиком в `_REQUIRES_MANUAL_CHECK_`, повреждённые архивы — каждый в свою папку
   внутри `_TROUBLES_` вместе с `_PROBLEM.txt`.

## Первый запуск на macOS или Linux

```bash
cd /Users/admin/Documents/UnpackModel_v3
source .venv/bin/activate
python api_core.py
```

Виртуальное окружение `.venv` уже создаётся при подготовке проекта. Если его
потребуется пересоздать:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

Для RAR на macOS нужен `unar`:

```bash
brew install unar
```

## Папки

По умолчанию архивы читаются из `original_archives/`:

```bash
python api_core.py
```

Можно указать входную и отдельную выходную папки:

```bash
python api_core.py /путь/к/архивам /путь/к/результату
```

Поддерживаемые архивы: ZIP и RAR. Максимальный размер архива и его
распакованного содержимого — 1,5 ГБ. Небезопасные пути, ссылки, дубликаты,
ZIP-бомбы и повреждённые архивы отклоняются.

## API

Ключ хранится только в локальном `.env`:

```dotenv
SBORKA_API_KEY=ваш_ключ
```

`.env` исключён из Git. Не добавляйте ключ в исходный код или журналы.

Проверить получение подзаказов отдельно:

```bash
python website_parser.py НОМЕР_ЗАКАЗА
```

Во время обработки программа показывает момент обращения к сайту, полученные
подзаказы, количество найденных макетов, число страниц каждого PDF и полный
план переименования. JPEG/TIFF считается одной стороной. Для `4-4`/`1-1`/`5-5`
допустим один двухстраничный PDF на заказ либо два одностраничных PDF
`face`/`back`. Для `4-0`/`1-0` нужен один одностраничный PDF на заказ.
Двухстраничный PDF сохраняется целиком и не разделяется.
Смешанные пары также допустимы, например одностраничный `face.pdf` и
`back.tif`. PDF с маркером `preview/превью` в имени не считается макетом.
Для CorelDRAW (`.cdr`) и Illustrator (`.ai`) действует правило «один файл на
один заказ»: если количество файлов равно количеству заказов, каждый файл
считается полным комплектом, включая заказы со сторонностью `4-4`/`1-1`.
Также допустимы два файла на двухсторонний заказ: если файлов ровно вдвое
больше, они группируются естественными парами «лицо, оборот»; явные маркеры
сторон в именах имеют приоритет над порядком.
Расширение PDF/TIFF/JPEG никогда не используется для определения лица или
оборота: формат нужен только для технического подсчёта страниц PDF.

## Спорные лицо и оборот через LM Studio

Запустите локальный сервер LM Studio на `http://127.0.0.1:1234` и задайте в
`.env`:

```dotenv
LOCAL_LLM_BASE_URL=http://127.0.0.1:1234/v1
LOCAL_LLM_MODEL=qwen/qwen3.8-27b
# LOCAL_LLM_VISION_MODEL=...   # по умолчанию = LOCAL_LLM_MODEL
LOCAL_LLM_TIMEOUT=90
LOCAL_LLM_API_TOKEN=            # LM Studio → Developer → API tokens
LOCAL_LLM_REASONING_EFFORT=none
```

- Без `LOCAL_LLM_MODEL` используется `google/gemma-4-e4b` — для обоих слоёв.
- Если в LM Studio включена авторизация, без `LOCAL_LLM_API_TOKEN` все запросы
  получают 401. Токен отправляется как `Authorization: Bearer …`.
- `LOCAL_LLM_REASONING_EFFORT=none` отключает «рассуждения» моделей вроде
  Qwen: вместе со строгой JSON-схемой они дают пустой ответ («LM Studio вернула
  пустой ответ»). Пустое значение не передаёт параметр вовсе.
- Модель должна поддерживать изображения, иначе визуальный слой не работает.

### Ollama на GPU-сервере (Proxmox)

Вместо LM Studio можно использовать Ollama в CT 200 `gemma-lxc` на узле
Proxmox9 (RTX 3050, 6 ГБ видеопамяти). Ollama совместима с тем же API:

```dotenv
LOCAL_LLM_BASE_URL=http://192.168.88.200:11434/v1
LOCAL_LLM_MODEL=gemma4:e4b
```

В 6 ГБ помещаются модели примерно до 4–5B (`gemma4:e4b`, `gemma4:e2b`); модели
27B туда не входят. Совместимость Ollama с `reasoning_effort` стоит проверить
тестом `llm_json_test.py` перед переходом.

Проброс GPU в контейнер: на хосте служба `nvidia-dev-nodes.service`
(`nvidia-modprobe -u -c=0`) создаёт `/dev/nvidia*` при загрузке, а в
`/etc/pve/lxc/200.conf` устройства подключены строками
`dev0: /dev/nvidia0,mode=0666` … `dev3: /dev/nvidia-uvm-tools,mode=0666`.
Проверка:

```bash
ssh root@10.20.2.72 'pct exec 200 -- nvidia-smi -L'
```

Безопасный тест только на JSON (архивы и файлы не изменяются):

```bash
.venv/bin/python llm_json_test.py --limit 5
```

Тест сначала получает реальные подзаказы с сайта и проверяет количество. Для
`4-4`, `5-5` и `1-1` требуется два файла на каждый заказ независимо от того,
TIFF это или JPEG. При несовпадении количества LM Studio не вызывается.
Предложения и найденные расхождения записываются в `llm_proposals.json`.
Для PDF инвентарный JSON проверяет правило «один PDF на заказ», но число
страниц проверяется только после распаковки, потому что в JSON содержатся лишь
имена файлов.

Для обработки настоящих архивов с обращением к LM Studio только в спорных
случаях:

```bash
python api_core.py --use-local-llm
```

Перед каждым переименованием, предложенным моделью, программа показывает
`старое имя → новое имя` и требует ответ `да` или `нет`. Без подтверждения
переименование не выполняется.

## Надёжность повторного запуска

Программа блокирует одновременный запуск для одной входной папки и ведёт
атомарный журнал стадии каждого заказа. Если процесс остановился после
переименования, следующий запуск завершит перенос архива и создание `.done`,
не переименовывая макеты повторно.

Устаревшая блокировка не удаляется автоматически. После проверки, что другой
экземпляр программы действительно не работает, её можно снять:

```bash
python api_core.py --break-stale-lock
```

Для нескольких подзаказов программа сначала использует полные номера заказов
из имён файлов. Если номеров нет, файлы группируются последовательно в
естественном порядке имён. Для контроля программа явно сообщает об этом
режиме перед построением плана. Запретить резервную последовательную
группировку можно строгим режимом:

```bash
python api_core.py --strict-order-ids
```

При `--use-local-llm` каждая спорная пара «лицо/оборот» передаётся в LM Studio,
а предложенное моделью переименование по-прежнему требует подтверждения.
До обращения к модели проверяются русские, украинские и английские словесные
маркеры (`лицо`, `лицьова`, `front`, `оборот`, `зворот`, `back` и другие),
отдельные сокращения, суффиксы `F/B`, `1/2` и порядок страниц в двухстраничном
PDF. Только если эти признаки не дали
однозначного ответа, модель
анализирует имена. Если этого недостаточно, третий слой
создаёт уменьшенные JPEG-превью TIFF/JPEG и выполняет визуальный анализ.
Исходные полноразмерные макеты не отправляются и не изменяются.
Перед переносом проблемного заказа программа показывает категорию, причину и
пути назначения. Каждый повреждённый архив получает свою папку
`_TROUBLES_/<имя архива>/` с самим архивом, `_PROBLEM.txt` (дата, инструмент,
причина) и частичной распаковкой, если она была. В итоговой сводке причины ручной проверки группируются.

## Деплой в UnpackModel LXC

После коммита локальные изменения можно отправить в CT 201 командой:

```bash
./deploy.sh
```

Скрипт передаёт только отслеживаемые Git-файлы и запускает тесты внутри
контейнера. Файлы `.env`, `.venv` и данные `/mnt/shared` не перезаписываются.
Для работы без запроса пароля один раз настройте SSH-ключ для `root@10.20.2.72`.
